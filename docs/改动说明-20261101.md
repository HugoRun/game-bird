## 三、玩法规则（数值基线，集中在 ConstData/GameProperties 便于调参）

1. **逃脱机制**：星越高越易挣脱（每星 5%）。下饵时掷骰，判定结果存于
   `catch_bird_star` 的负值标记（`-(star+1)`，不改表结构的约定）；收网时逃脱给一半
   经验安慰奖。粘性道具（effect_type=1，鼻涕/浆糊/胶水）在下饵页勾选消耗，逃脱率减半。
2. **捕捉数值**：成长值随机 500~1500（原写死 1000）、克制值随机 0~100（原写死 0）。
   鸟笼加成：`base_cage.param`%，经验笼加经验、重量笼加体重（按 func 文案区分）。
3. **陷阱耐久**：收网扣 1 次；损坏的陷阱不能下饵，需到包裹更换。仓库上限
   `game.bird-storage-capacity`（默认 50），满仓拒收并保留捕捉状态。
4. **训练**：`base_train.min_exp` × 已训练分钟 = 鸟经验；鸟升级每级需 `level×100`
   经验，上限为训练场 `max_level`；训练/配对中的鸟 `is_lock` 锁定不可出售。
5. **配对**：同种产同种、异种产低阶一方；星级=父母均值±1；体重=父母均值±25%
   （叠加巢穴/婚姻加成）；巢穴 effect_type=3 减孵化时长、=1 赠产出鸟经验、=2 加体重。
6. **好友配对**：邀请落双方 `role_birth`（发起方 `birth_end_time=0` 待确认）。
   因 `match_role_id` 是 int 列存不下 UUID，对方定位走 `match_bird_id`（精确）。
7. **战斗**：战力=鸟等级×20+星级×50+成长/10+角色等级×10；胜率=我方占比（15%~85%）；
   胜利抢对方 1% 金币（封顶 1000）+ 经验；失败无损失；冷却 5 分钟；每战扣鸟笼耐久 1。
8. **任务**：每日登录（当天去重，完成即领 500）、捕捉（300）、购买（200）三类触发器
   （`TaskTriggerService`），任务页/主页任务位接线。
9. **签到**：100×连签天数（封顶 700），第 3 天赠 5 钻、第 7 天赠 20 钻，断签重置。
10. **经济闭环**：钻石获取=签到+战斗奖励；钻石消耗=陷阱加速。改名卡/性别卡建角各赠 1，
    之后改名/换性别需购卡。

## 四、重构与代码组织

- **TrapService / TrapServiceImpl**：下饵/收网全部规则从 Controller 下沉（Controller 只剩
  参数与消息渲染），事务边界与文案由 service 统一。
- **PackUseService**：5 类道具装载 + 道具效果分派的唯一实现；`@Transactional` 只标注
  Controller 直接调用的 public 方法（自调用不过代理的规范与 ShopPurchaseService 一致）。
- **GameEventService**：log_tree 事件写入/查询的唯一入口（旁路失败不抛出）。
- **TaskTriggerService / SignInService / OnlineCounterService**：任务触发、签到、在线统计
  各自收敛成单一服务；OnlineCounterListener 由纯日志改为真实注册表。
- **RolePackAssembler.assembleOne**：单条包裹记录装配（道具目标页使用）。
- **GameConfigGateway.getBaseBirdList**：试管孵化/遍历场景的配置访问口。
- 收网/收尾后 `trap/over` 结算页、`pack/bait.html` 使用链接（漏传 trapId 必报错的 bug）
  一并修复。

## 五、账号安全

- `PasswordHasher`（common/util）：BCrypt + 存量明文兼容校验 + 透明升级。
- 登录验证通过后即时改写哈希；注册直接存哈希；改密强制新口令 ≥6 位。
- `Account` 实体无 @Data 的约定未动。
